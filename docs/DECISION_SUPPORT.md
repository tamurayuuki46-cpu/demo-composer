# v0.3 作曲判断支援

## 目的と導線

ドラフト → 複数候補 → 比較 → 選択 → 修正。1案を自動完成させず、現在案を尊重する。
既存画面の「作曲の判断」を折りたたみで追加し、下部タブを増やさない。

| 要望 | 実装場所 / 動作 |
| --- | --- |
| A/B比較 | Melodyの既存候補と、各画面の判断パネル。Chordは選択Preset進行全体も比較できる。A/Bは同じ範囲・BPM・伴奏・音色で、小節頭から再生。音色比較では選んだパートの音色だけ、コード比較ではコードだけが違う |
| 曲の設計メモ | Hub。フック / 聴かせたい場所 / 緊張→解決 / サビの変化 / 参考曲から借りる考え方。5軸の方針も各1行 |
| Section役割 | Arrange。種類別の例はプレースホルダーだけで、自由入力して保存。音符や小節数は変えない |
| メロディ分析タグ | Melody / 裏メロ。隣接・跳躍・反復・移高同型候補と、既存の和声・非和声音分析。10概念の人の分析タグを保存。リック / コール＆レスポンスを自動断定しない |
| ハーモニー目的 | Chord。指定小節へ「安定/緊張/浮遊/切なさ/明るさ/意外性/転調感/解決感」。既存感情タグ、自動コード役割とは別の本人の意図 |
| 1要素だけ変える | Melody:末尾2音の音高 / リズム / 音高。Chord:コード1個 / コード音域。裏メロ:裏メロだけ。Sound:仮音色だけ。少数候補 → A/B → 採用 |
| 未決定項目 | Hub。メモ未記入、Section役割未決定、裏メロ/音色/Section変化未確認、採用理由未記入。未決定 / 決定済み / 今回は不要。音があることと決定済みを混同しない |

## 範囲と比較

- 比較時のProjectコピーを固定し、ID / revision照合で古い候補を拒否する。通常編集・Undo/Redo・Importで比較を破棄。
- 未採用候補、試聴、比較切替はProject/Undo/AutoSaveを変更しない。理由なしでA保持も変更なし。
- B採用は対象Note/コード/音色だけを変更し、任意の理由と一緒にUndo1手で戻せる。
- Melody/Counterは指定した1/2/4/8小節だけ。末尾2音は範囲内の最後の2音の音高だけで、タイミング・長さ・強さを保持。
- リズムだけは音高・長さ・強さを保持し、元の空白の範囲で開始位置をずらす。変更できる空白がなければ「同じ音」と表示し採用は無効。無理に音を短縮しない。
- コード1個はroot / degree / timingを保持してQualityだけ変える。Preset進行はコード列全体を明示的に置換し、他Trackを保持。
- Bassがある間はコード採用を拒否する。A/B試聴では両案でBassを外すことを表示。Bassを自動消去/再生成しない。
- 音色・コード音域の保存は曲全体の対象パートに適用する。試聴範囲だけの音色保存ではないことを表示。
- ボイシングは音域lower/center/upperの最小選択。MIDIのコード音域にも反映。音の詳細な配列や各声部編集はDAWに任せる。
- 音ごとの差分は音高・開始拍・長さ・強さを表示。未採用案をExportしない。

## データと互換性

Version: v0.3-dev。Schema: 3。PPQ 480 / 4/4固定 / project.json正本は維持。
新しい言葉の領域はmetadata.composition、Section purpose、Chord purposes。詳細DATA_SCHEMA.md。
Schema 1/2のProjectは起動時にrevision別退避し、音楽フィールドを保持して3へ移行。DB_VERSION=1 / Object Store追加なし。
Schema 3を旧アプリへ渡す前方互換はない。復元Branchだけに戻す場合も、旧schemaのProjectバックアップを使う。
MIDI Importは今の設計メモと採用履歴を保持し、JSON Importはファイル内の設計意図で置き換える。どちらもUndo可能。
ログは採用当時の小節範囲。後のSection移動には追従しない。最大1000件・表示30件・全件JSON保存。超過時は古いログを削除せず操作を拒否。
AI相談とCubase用メモへ設計意図・5軸・最近の理由を含める。外部へ自動送信しない。

# v0.3 骨子作り支援 計画（骨子レシピ）

状態: 計画のみ（コード未変更）。実装はこの文書への合意後。
作成: Claude（ChatGPTの「骨子作り支援12案」＋Claudeの拡散案のレビュー結果）

## 目的

新しい独立機能を12個足すのではなく、既存のHub / Chord / Melody / Rhythm / Arrange / Soundを、初心者が迷わず進める**一本の骨子作りフロー**につなぐ。判断基準は「この変更で、スマホ上の作曲判断がしやすくなるか？」。

## 12案の扱い

| 案 | 扱い | 理由 |
| --- | --- | --- |
| 1 感情の変化を言葉で並べる | 統合（第1段階） | 感情曲線に言葉ラベルを付けるだけ |
| 2 問い→答え型メロディ | v0.4 | Melody候補の型の追加。Melody Module内で完結 |
| 3 4小節質問カード | v0.4（Variationへ吸収） | Section Variationのワンタップ候補と重複 |
| 4 緊張度カーブ | 見送り | Energyと別軸の2本目になり初心者が混同する |
| 5 曲の芯 | 第3段階 | 「聴かせたいもの」1タグに統合 |
| 6 Sectionの役割質問 | 第3段階 | 5と同じ仕組み |
| 7 温度感 | 削る | Sound Sketchの方向性タグ（Warm / Dark等）と重複 |
| 8 期待→裏切り | 削る（文言のみ） | Transition（Stop / Drop）が実体。手引きに一文を足す |
| 9 モチーフ変形 | v0.4以降 | Melody側の新機能 |
| 10 骨子レシピ | **第1段階の中心** | 流れをPreset化する。最大のレバー |

## 制作フロー（目標）

1. 出発点（音）: 既存のジャンル × 気分 → Key / BPM / コード / ドラム / 音色（Hub）
2. 出発点（流れ）: **骨子レシピ** → 構成 / Energy / つなぎ / 各Sectionの役割（Arrange）
3. 作る: 既存のChord / Melody / Rhythm / 裏メロの候補
4. 確認: 骨子チェック（「次に決める1つ」「今は後でOK」）
5. 渡す: Cubaseメモ → MIDI Export

## 第1段階: 骨子レシピ

### 仕様

- レシピ = 感情の言葉 + Sectionの並び（kind / bars / energy / transition）。完成曲ではなく、**作曲判断の流れ**のPreset。
- 適用すると `structure.sections` を置き換える。保存先は既存の `kind` / `bars` / `energy` / `transition`。**Schema変更なし**（DATA_SCHEMA.md「structure.sections」の追記済み項目のみ使用）。
- 音符・コード・ドラムは変えない。適用前に確認、`↶` で戻せる（既存の `applySectionOp` 経由）。
- 画面: Arrangeの「感情曲線」の隣に `骨子レシピ`（開閉）。各カードに感情の言葉・山の形（Low / Mid / High）・小節数を表示し、`適用` ボタン1つ。HubのStarting Point適用後に「次は流れを決める → Arrange」の導線を1行足す。
- 実装方針: `src/arrange/skeleton-recipes.js`（定数テーブル + 検証）。Projectを読み書きしない純粋データ。Module間の直接依存は作らない。
- 各Sectionの役割（表示のみ・保存しない）: イントロ=雰囲気を示す / Aメロ=情報を出す / Bメロ=期待を上げる / サビ=一番覚えてほしい / 間奏=息継ぎ / Cメロ=景色を変える / アウトロ=余韻。

### レシピ案（8個）

表記: `種類 小節 Energy → つなぎ`（つなぎは次のSectionへ。Keepは省略）。

1. **切ない→解放**（静か → 期待 → 解放 → 余韻）
   イントロ4 L ／ Aメロ8 L ／ Bメロ8 M → Stop ／ サビ8 H ／ アウトロ4 L
2. **王道 1番サビ型**（静か → 期待 → 解放 → 一息 → もう一度）
   イントロ4 L ／ Aメロ8 L ／ Bメロ8 M → Fill ／ サビ8 H ／ 間奏4 M ／ Aメロ8 L ／ Bメロ8 M → Fill ／ サビ8 H ／ アウトロ4 L
3. **ラスサビ最大型**（控えめ → 落とす → 最大）
   イントロ4 L ／ Aメロ8 L ／ Bメロ8 M → Build ／ サビ8 M ／ Cメロ8 L → Stop ／ サビ8 H ／ アウトロ4 L
   （Energyは3段階のため、1番サビをMid、ラスサビをHighにして差を作る）
4. **徐々に上昇型**（静か → じわじわ → 最大）
   イントロ4 L ／ Aメロ8 L ／ Aメロ8 M → Build ／ サビ8 H ／ サビ8 H ／ アウトロ4 L
5. **一度落として最後に最大**
   イントロ4 L ／ Aメロ8 L ／ Bメロ8 M → Fill ／ サビ8 H ／ Cメロ8 L → Drop ／ サビ8 H ／ アウトロ4 L
6. **サビ先行**（先に聴かせる → 戻る）
   サビ8 H ／ Aメロ8 L ／ Bメロ8 M → Build ／ サビ8 H ／ アウトロ4 L
7. **ダンス・ループ**（ずっと動く → 山）
   イントロ4 L → Build ／ Aメロ8 M ／ サビ8 H → Fill ／ 間奏4 M ／ Aメロ8 M ／ サビ8 H ／ アウトロ4 L
8. **バラード**（静かに始まり静かに終わる）
   イントロ4 L ／ Aメロ8 L ／ Aメロ8 L ／ Bメロ8 M → Build ／ サビ8 H ／ アウトロ8 L

全レシピが `MAX_SECTIONS=24` / `MAX_SECTION_BARS=32` / `MAX_TOTAL_BARS=128` に収まる（最大はレシピ2の60小節）。

### テスト

- `scripts/recipe-smoke-test.mjs`（`npm run test:recipes`、CI対象）: 全レシピが Section の kind / bars / energy / transition の制約を満たすこと、最後のSectionにtransitionを持たないこと、適用後に `validateProject` が通ることを確認。
- 360pxで横スクロールなし、適用 → `↶` で元に戻ることをブラウザで確認。
